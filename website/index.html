    Why Duo is different

    For a decade, an iPhone app could assume one rectangle of glass. iPhone Duo folds, unfolds, rotates, and splits — and your app's window changes size while someone is using it. Apps built with the iOS 27 SDK mostly resize; only apps built with Xcode 27.1 (build 27A9275, Swift 6.4) and the iOS 27.1 SDK use the full 7.6″ inner display and earn the “Optimized for iPhone Duo” App Store badge. Older builds simply letterbox.
    Xcode 27.1 also gives you a Device Hub folding simulator and alternative-display previews, so you can test every posture without owning the $1,999 hardware. DuoReady's job is everything before that step: find the source-level problems, in minutes, while they're still cheap to fix.

    How it works

    1

    Run the scan

    Point DuoReady at your app's source: node src/cli.js scan /path/to/your-app. It walks your JS/TS and Swift files plus your Podfile, project file, and config, and prints a grouped report with file:line evidence.

    2

    Fix what it flags

    Work the prioritized list top-down. DuoReady ships drop-in React code to do it with — a useDuoLayout hook and a DuoSplitView component that go two-column unfolded and single-column folded, keeping your place across the fold.

    3

    Test, build, ship

    Fold, unfold, rotate, and Split-View every main screen in the Device Hub simulator. Then build with Xcode 27.1 and submit through App Store Connect / TestFlight — that's the step that actually earns the badge.

    22 checks, 7 groups

    14 checks are automatic — judged from your source, with evidence. 8 are flagged manual and left out of the score's denominator, because no scanner can honestly judge them from code alone: hinge behavior, playback and payment continuity across a fold, Split View testing, and Instruments profiling are yours to test.

    SDK & Build auto + gate

    iOS 27.1 SDK / Xcode 27.1 signal, deployment target, Hermes, and New Architecture readiness.

    Adaptive Layout auto

    useWindowDimensions instead of one-time size reads, no fixed width or device checks, two-column when wide, single-column when compact.

    Fold & Posture mostly manual

    Hinge-aware layout and posture changes — open, closed, partially folded, tent — tested, not assumed.

    State Continuity auto + manual

    Scroll position, form text, playback, sheets, uploads and payments must survive a fold, unfold, or rotate.

    Split View & Multitasking auto + manual

    Your layout must hold up when your window is half the inner screen, next to another app.

    Outer Display auto + manual

    The 5.4″ outer screen is a real surface — content and camera previews that use it, checked and tested.

    Performance for A20 Pro auto + manual

    Rendering and resize cost on the new chip, with Instruments profiling flagged manual.

    Drop-in React code included

    react/useDuoLayout.ts and react/DuoSplitView.tsx ship in the repo, ready to copy into your app.

    The hard gate: if your project shows no iOS 27.1 SDK / Xcode 27.1 signal, the verdict is capped at “Not Badge-Ready — letterbox risk” regardless of score. A high score on an old SDK still letterboxes.

    Run it your way

    One command for a human-readable report, flags for machines and CI — and an action.yml, so you can run DuoReady as a GitHub Action in your own repo.

    • --json  machine-readable report
    • --md report.md  write a Markdown report file
    • --fail-below 80  exit non-zero in CI when the score drops

node src/cli.js scan /path/to/your-app --fail-below 80

    Honest limits

    DuoReady tells you what your source signals — nothing more. Read this before you quote a score.

    • A scan is not proof of the badge. It reads source signals. Only a real build with Xcode 27.1, submitted through App Store Connect, earns “Optimized for iPhone Duo.”
    • It does not compile, run Xcode, run the Duo simulator, or submit to Apple. Those steps are still yours, in Device Hub and App Store Connect.
    • You still need a Mac with Xcode 27.1 and an Apple Developer account to build and ship a Duo-ready app.
    • It's React-first. It also reads Swift, Podfile, and project-file signals, so a pure-native Swift app gets a partial audit — not the full 22-check picture.
    • 8 of the 22 checks are manual on purpose. They're excluded from the score rather than guessed at.
